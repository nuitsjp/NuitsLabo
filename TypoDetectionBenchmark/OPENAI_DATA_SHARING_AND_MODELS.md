# OpenAI API データ共有プログラム（無料枠）および現行モデル包括調査レポート

本書は、100〜140文字程度の日本語文章における「誤字・脱字の自動補正タスク」を想定し、OpenAI の **データ共有プログラム（Data Sharing Program / Complimentary Tokens）の仕組み**、**ユーザーアカウント（Build ティア）に付与される無料枠**、および **全対象モデルの公式トークン単価・適用範囲** を網羅的に整理した調査レポートです。

---

## 1. エグゼクティブサマリー

1. **データ共有による無料枠（Complimentary Tokens）の存在**:
   - API の入出力を OpenAI のモデル学習・研究改善に共有（オプトイン）することで、対象組織に **日次の無料トークン枠** が自動付与される。
   - ユーザーのアカウント（**Build ティア**）では、毎日以下の 2 つのグループそれぞれに無料枠が付与される。
     - **大容量枠（250 万トークン / 日）**: `gpt-5.6-luna`, `gpt-5.4-mini`, `gpt-4o-mini` 等 ➡ **1日約 8,000〜10,000 件の補正が完全無料**
     - **標準枠（25 万トークン / 日）**: `gpt-6-luna`, `gpt-6.1-sol`, `gpt-6-astra`, `gpt-4o`, `o3` 等 ➡ **1日約 800〜1,000 件の補正が完全無料**
2. **`gpt-6-luna` の優位性**:
   - 最新の軽量モデル `gpt-6-luna` も **25 万トークン/日の無料枠対象** に含まれている。
   - トークン単価自体も **入力 $0.10 / 出力 $0.50 per 1M tokens** と極めて安価であり、無料枠超過後も **1件あたり約 0.012 円（1万件で約 120 円）** で運用可能。
3. **アカウントのレートリミット（Rate Limits）の潤沢さ**:
   - ユーザーの Build ティア環境では、`gpt-6-luna` や `gpt-4o-mini` に対して **2,000,000 TPM（毎分200万トークン） / 5,000 RPM（毎分5,000リクエスト）** が割り当てられており、速度制限に抵触する懸念はない。

## 2. データ共有プログラム（Data Sharing Program）の仕様と制約

公式ヘルプ記事（Article 10306912、6614457）に基づく主要仕様・制約事項です。

### ① 有効化と適用
- **設定場所**: `Settings` > `Organization Settings` > `Data Controls` > `Sharing`
- **項目**: 「Share inputs and outputs with OpenAI」を **Enabled** にして保存。
- **適用方式**: 設定が有効化された組織・プロジェクトからの対象モデルへの通常リクエストに対し、毎日無料トークンが自動充当される。

### ② 重要な制約事項（注意点）
1. **Tool use（ツール呼び出し）は無料枠対象外**:
   - **Function calling** や **Retrieval / Code Interpreter** などのツール機能を使用した場合、無料枠は適用されず **通常課金** となる。
   - ➡ **対策**: 誤字補正処理は、ツール呼び出しを伴わない純粋なテキストプロンプト（Chat Completions / Responses）で実装する。
2. **アカウントのクレジット残高（Credit balance）が必要**:
   - 無料枠を利用する場合でも、アカウントのクレジット残高が $0 だとシステム側で API リクエスト全体が弾かれる場合がある。
   - ➡ **対策**: 最低限のプリペイド残高（$5 程度）を維持しておくことが推奨される。
3. **残量メーターの非表示**:
   - 当日の残り無料トークン数をリアルタイム表示する専用メーターはない。
   - ➡ **確認方法**: [Usage ダッシュボード](https://platform.openai.com/usage) で、使用トークン量（Activity）が発生しているにもかかわらず請求コスト（Cost）が $0 のまま推移しているかを確認する。
4. **データの機密性**:
   - 送信した文章が OpenAI のモデル学習に利用されるため、社外秘・個人情報を含む文章の取り扱いには留意が必要。

| モデル | トークン制限 (TPM) | リクエスト制限 (RPM) | バッチ制限 (TPD) |

## 5. 誤字補正タスクにおける推奨運用設計

### ① 推奨アーキテクチャ案

```
[ユーザー入力: 100〜140文字]
         │
         ▼
【Step 1: 高速・低コスト判定】
  OpenAI Decisions API (gpt-6-luna / 閾値 0.4) 
  または TypeSafe AI (jev-latest / 閾値 0.3)
         │
    誤字脱字あり？
   ├── No  ─▶ そのまま確定・完了 (追加コスト 0)
   └── Yes ─▶ 【Step 2: 誤字補正の実行】
                OpenAI 無料枠モデルで補正テキストを生成
```

### ② 補正モデル（Step 2）の選定パターン

| パターン | 採用モデル | 日次無料枠 | 超過時コスト | 特徴・推奨用途 |
| :--- | :--- | :---: | :---: | :--- |
| **パターン A<br>（最新世代・最高精度）** | **`gpt-6-luna`** | **25 万トークン**<br>(約800〜1,000件/日) | 約 0.012 円 / 件<br>(1万件で約120円) | **【推奨】** GPT-6 世代の高い日本語理解力と指示追従性を活かし、余計な意訳を排した正確な誤字補正が可能。 |
| **パターン B<br>（超大容量・完全無償）** | **`gpt-5.6-luna`**<br>または **`gpt-4o-mini`** | **250 万トークン**<br>(約8,000〜10,000件/日) | 約 0.015〜0.028 円 / 件 | 毎日数千件規模の文章を完全無償枠の範囲内だけで運用したい場合に最適。 |

## 6. 次の検証ステップ

1. **誤字補正プロンプトの設計**:
   - 入力文章に対し、「誤字・脱字・変換ミスのみを修正し、原文の文体・語彙・ニュアンスを変更しない」厳格なシステムプロンプトを作成。
2. **モデル別補正テスト（検証スクリプトの実装）**:
   - テストデータセット（誤字脱字文15件）に対し、`gpt-6-luna`、`gpt-5.6-luna`、`gpt-4o-mini` で補正を実行。
   - **修復成功率**、**余計な改変（意訳・過剰修正）の有無**、および **生成速度（レイテンシ）** を比較・評価。
