## 1. エグゼクティブサマリー

```
【入力: 100〜140文字の日本語テキスト】
         │
         ▼
【Step 1: 高速・低コスト判定】
  ・OpenAI Decisions (gpt-6-luna / 閾値 0.4): 再現率 100%（見逃しゼロ） / 280 ms
  ・TypeSafe AI (jev-latest / 閾値 0.3): 適合率 100%（誤報ゼロ） / 162 ms
         │
    誤字脱字あり？
   ├── No  ─▶ そのまま通過・確定（追加コスト 0 円 / 即時完了）
   └── Yes ─▶ 【Step 2: 自動補正（Prompt v3）】
                ・gpt-5.6-luna (250万tok/日 無料枠): 1.58 秒 / 正常文100%維持 & 誤字100%修復
                ・gpt-6-luna   (25万tok/日 無料枠):  2.05 秒 / 正常文100%維持 & 誤字100%修復
```

1. **高速判定（Step 1）**:
   - **OpenAI Decisions API** は閾値 0.4 で **再現率 100.0%（見逃し 0 件）** を達成。
   - **TypeSafe AI System One** は **中央値 162 ms（平均 177 ms）という圧倒的な低遅延** と適合率 100%（空振り 0 件）を実証。
2. **完全無料枠（Data Sharing Program）の活用**:
   - ユーザーアカウント（**Build ティア**）において、入出力データ共有を有効化することで、**`gpt-5.6-luna` は毎日 250 万トークン（約 6,500 件/日）**、**`gpt-6-luna` は毎日 25 万トークン（約 630 件/日）** が完全無料で利用可能。
3. **プロンプト精緻化によるブレークスルー（Step 2）**:
   - 「修正すべき対象」と「絶対に維持すべき表記ゆれ」の境界を具体例付きで定義した **Prompt v3** により、**`gpt-6-luna` および `gpt-5.6-luna` の両モデルで「正常文維持率 100.0%」かつ「誤字修正率 100.0%」（全30件パーフェクト）を達成**。

## 2. 第1部：誤字脱字の高速判定ベンチマーク（OpenAI Decisions vs TypeSafe AI）

100〜140文字（実測120〜126文字）の日本語テキスト30件（正常文15件 / 誤字脱字文15件）に対し、二値分類（誤字の有無）の性能を比較しました。

### ① 性能比較サマリー

| 評価軸 | OpenAI Decisions API (`gpt-6-luna`) | TypeSafe AI System One (`jev-latest`) | 優位性・特徴 |
| :--- | :---: | :---: | :--- |
| **平均応答速度** | 425.5 ms | **177.0 ms** | **TypeSafe AI が約 2.4 倍高速** |
| **中央値 (Median)** | 280.0 ms | **162.0 ms** | TypeSafe AI は遅延のブレが極小 |
| **P95 応答速度** | 1,289.0 ms | **249.0 ms** | OpenAI は一部 1 秒超のスパイクあり |
| **最適閾値での正解率** | **90.0%** (閾値 0.4) | 86.7% (閾値 0.3) | 総合正解率は OpenAI が優位 |
| **再現率 (見逃し防止)** | **100.0% (15/15 検出)** | 73.3% (11/15 検出) | **OpenAI は見逃しゼロを達成** |
| **適合率 (誤検知防止)** | 83.3% (3件過検出) | **100.0% (過検出ゼロ)** | **TypeSafe AI は正常文を誤判定しない** |
| **F1 スコア** | **0.909** | 0.846 | 総合判別性能は OpenAI が優位 |
| **1件あたり実コスト** | $0.0000206 (約 0.0032 円) | **$0.0000142 (約 0.0022 円)** | **TypeSafe AI が約 31% 安価** |

### ② 判定特性とエラー傾向
- **OpenAI Decisions**: 「お願い足します」「概算見張り等」などの同音異義語、カナ反転「サトイ」、促音抜け「アプリケション」を確率 0.83〜0.96 で確実に検知。閾値 0.4 で全15件の誤字を 100% 網羅。
- **TypeSafe AI**: 正常文に対する安定性（偽陽性 0 件）が極めて優秀。助詞重複「がが」や語尾脱落「存じま」は即座に捉えるが、微細な助詞抜け（「機器冗長化」）や促音抜けの感度がやや控えめ。

第3部の補正タスクでパーフェクトを達成した知見（誤字と表記ゆれの具体例境界定義）を判定タスク（Instructions / Criteria）にも適用して再実測を行いました。

| サービス | 最適化前 (F1 / 再現率 / 適合率) | 最適化後 (F1 / 再現率 / 適合率) | 検証から得られた知見と結論 |
| :--- | :---: | :---: | :--- |
| **TypeSafe AI** (`jev-latest`) | **F1: 0.846** (再現 73.3% / 適合 100%) | **F1: 0.933** 🎉 (再現 93.3% / 適合 93.3%) | **正解率 93.3%（28/30件）へ大幅向上！** 助詞抜けや促音抜けの検知力が大幅に改善し、見逃しが 4件 ➡ 1件（ID:22「修正バッチ」のみ）へ激減。応答速度も 288ms と高速を維持。 |

## 3. 第2部：OpenAI データ共有プログラム（無料枠）の仕様と単価

OpenAI Developer Platform において、**「Share inputs and outputs with OpenAI」** を有効化することで付与される日次無料トークン枠（Complimentary Tokens）の仕様です。

### ① Build ティアにおける付与グループ

| グループ | 1日あたりの無料枠 | 対象モデル（抜粋） | 100〜140文字 補正換算 |
| :--- | :---: | :--- | :---: |
| **大容量枠** | **2,500,000 tokens / 日** | **`gpt-5.6-luna`**, `gpt-5.6-terra`, `gpt-5.4-mini`, `gpt-5-mini`, `gpt-4o-mini`, `o4-mini` 等 | **約 6,500 件 / 日 完全無料** |
| **標準枠** | **250,000 tokens / 日** | **`gpt-6-luna`**, `gpt-6.1-sol`, `gpt-6-astra`, `gpt-5.4`, `gpt-4o`, `o3`, `o1` 等 | **約 630 件 / 日 完全無料** |

### ② 運用上の重要制約
1. **Tool use（ツール呼び出し）は無料枠対象外**: Function calling 等を利用すると通常課金となるため、テキストプロンプトで実装する。
2. **プリペイド残高要件**: アカウントのクレジット残高が $0 だとブロックされる仕様があるため、最低限（$5程度）の残高を維持する。
3. **レートリミット**: ユーザー環境（Build ティア）では `gpt-6-luna` / `gpt-5.6-luna` ともに **2,000,000 TPM / 5,000 RPM** と最大枠が付与されており、制限到達の懸念はない。

## 4. 第3部：誤字補正ベンチマークとプロンプト改善の変遷（v1 ➡ v2 ➡ v3）

Chat Completions API を用いた誤字補正タスクにおいて、プロンプトの記述を 3 段階にわたって改善し、挙動とスコアの推移を検証しました。

### ① 投入したプロンプト全文

#### 【Prompt v1: 初期標準プロンプト】
> あなたは高精度な日本語文章校正AIです。入力された文章を検査し、誤字・脱字・変換ミス・助詞の脱落や重複などの誤りがあれば修正してください。原文の文体・ニュアンス・表現は極力そのまま維持し、必要最小限の修正を行ってください。解説や前置きは一切出力せず、修正後の文章のみを出力してください。誤字脱字がない場合は、入力文章をそのまま完全一致で出力してください。

#### 【Prompt v2: 厳格維持プロンプト（推敲・表記ゆれ禁止）】
> あなたは厳格な日本語文章校正AIです。  
> 入力された文章を検査し、明らかな【誤字・脱字・同音異義語の誤変換・カナ打ち間違い・助詞の脱落や重複】のみを最小限修正してください。  
>   
> 【厳守すべき絶対ルール】  
> 1. 推敲・リライトの禁止:  
>    - より自然な表現への言い換え、語彙の変更、文章の改善・リライトは固く禁じます。  
>    - 例: 「獲得」を「取得」にする、「スケジュールの」を「のスケジュールの」にする等の一切の言い換えは禁止です。  
> 2. 表記ゆれ・句読点変更の禁止:  
>    - 漢字とひらがなの使い分け（例: 「予定通り」と「予定どおり」）、半角スペースの有無（例: 「OAuth2.0」と「OAuth 2.0」）、読点の追加・削除は、誤字脱字ではないため絶対に変更してはなりません。  
> 3. 原則完全維持:  
>    - 確信が持てる致命的な誤字脱字・文法崩壊がない場合は、一文字も変更せず入力文章と完全一致で出力してください。  
> 4. 出力形式:  
>    - 前置き・解説・挨拶は一切含めず、修正後の文章（または完全一致の原文）のみを出力してください。  

#### 【Prompt v3: 境界明示プロンプト（具体例付き境界定義）】★決定版
> あなたは最高精度の日本語校正スペシャリストです。  
> 入力文章を精査し、【客観的な誤字・脱字・変換ミス・文法エラー】のみをピンポイントで修正してください。  
>   
> 【修正すべき対象（これらは確実に修正すること）】  
> 1. 明らかなタイポ・誤字・カナ誤り:  
>    - 促音や長音の抜け（例: 「アプリケション」➡「アプリケーション」）  
>    - 文字の入れ替わり（例: 「サトイ」➡「サイト」）  
>    - 濁音・半濁音の誤変換（例: 不具合修正の文脈における「修正バッチ」➡「修正パッチ」）  
>    - 送りがな・捨て仮名の誤り（例: 「ご返信下り」➡「ご返信ください」、「となつております」➡「となっております」）  
> 2. 脱字・文法崩壊:  
>    - 文字や語尾の脱落（例: 「能性がある」➡「可能性がある」、「存じま」➡「存じます」）  
>    - 助詞の脱落による文法不成立（例: 「機器冗長化切り替え」➡「機器の冗長化切り替え」）  
>    - 不要な重複（例: 「がが」➡「が」、「経理部前経理部前」➡「経理部前」）  
> 3. 明らかな同音異義語の誤変換・誤用:  
>    - 文脈に明らかに合わない漢字誤り（例: 「お願い足します」➡「お願いいたします」、「見張り等」➡「見積もり等」、「受項」➡「受講」、「台幅な」➡「大幅な」、「批評的な課題」➡「重大な課題」）  
>   
> 【絶対に修正してはならない対象（厳守ルール）】  
> 1. 表記の好み・ゆれの維持:  
>    - 「予定通り」と「予定どおり」、「すべて」と「全て」など、どちらも日本語として正しい表記ゆれは絶対に変更しないこと。  
>    - 半角スペースの有無（「OAuth2.0」と「OAuth 2.0」など）や、句読点（読点）の勝手な追加・削除は禁止。  
> 2. 意訳・推敲・言い換えの禁止:  
>    - 意味が完全に通っている自然な語彙を、別の同義語に言い換えてはならない（例: 「獲得」を「取得」に変える、「各自」を「各自の」に変える等の推敲は厳禁）。  
> 3. 原則完全一致:  
>    - 上記の「修正すべき対象」に該当する明確な誤りがない文章は、一文字も変更せず入力文章のまま完全一致で出力すること。  
>   
> 【出力形式】  
> 解説・前置き・引用符などは一切出力せず、修正後（または完全一致）の本文のみを出力してください。
