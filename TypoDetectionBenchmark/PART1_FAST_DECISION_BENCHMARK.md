# 第1部：誤字脱字の高速判定ベンチマーク（OpenAI Decisions vs TypeSafe AI）

100〜140文字（実測120〜126文字）の日本語ビジネス・テック文章30件（正常文15件 / 誤字脱字文15件）を対象に、二値分類（誤字の有無判定）の精度・レイテンシ・トークン消費・コストを比較検証したレポートです。

---

## 1. 総合評価サマリー（双方の最適プロンプトによる対比）

検証の結果、**OpenAI Decisions API と TypeSafe AI System One ではモデル特性が根本から異なり、それぞれ適正なプロンプトの設計方針が正反対である** ことが判明しました。

- **TypeSafe AI (`jev-latest`)**:
  - ルール厳格型の小型分類モデル。Criteria を「何が誤字で、何が表記ゆれか」まで具体的に指示する **最適化プロンプト（精緻化Criteria）** を与えることで、**正解率 93.3%（F1: 0.933 / 見逃し1件のみ）** へ大幅進化。
- **OpenAI Decisions API (`gpt-6-luna`)**:
  - 大規模言語モデルベースの確率判定。指示を長文化すると過剰に疑心暗鬼となり正常文の誤検知（偽陽性）が激増するため、**シンプル指示（標準プロンプト）** の方が **正解率 90.0%（再現率 100.0% / 見逃しゼロ）** の最高性能を発揮。

## 2. チューニング過程における挙動とスコア・コストの変化

### ① TypeSafe AI System One の変化過程
- **初期状態 (汎用Criteria)**:
  - Criteria: `Determine whether the following Japanese text contains any typos, missing characters, grammatical errors, or awkward collocations.`
  - 結果: 正常文の誤報は 0 件（適合率 100%）だったが、助詞抜け（「機器冗長化」）や促音抜け（「アプリケション」）など 4 件を見逃し、再現率 73.3%（F1: 0.846）にとどまっていた。
- **チューニング後 (具体例境界Criteria)**:
  - Criteria: 「修正すべき誤り（促音抜け、助詞脱落、同音異義語誤字、文字脱落など）」と「許容すべき表記ゆれ（予定通り/予定どおり、スペースの有無）」を具体例付きで明示。
  - 結果: 見逃しが 4件 ➡ **1件（ID:22「修正バッチ」のみ）へ激減**。再現率は 93.3% に急上昇し、**正解率 93.3%（F1: 0.933）** を達成。レイテンシも平均 288.7 ms と 300 ms 未満を維持。
  - コスト影響: Criteria の文字数が増加したものの、TypeSafe AI の課金体系上、1件あたり約 0.002〜0.004 円レンジに収まり実用影響は軽微。

### ② OpenAI Decisions API の変化過程
- **初期状態 (シンプル指示)**:
  - Instructions: `Analyze the provided Japanese text and determine if it contains any clear typos, grammatical errors, or unnatural wording.`
  - 結果: 閾値 0.4 で **再現率 100.0%（全15件検出・見逃しゼロ）**、F1: 0.909 を記録。正常文で 3 件の過検出があった。
- **チューニング後 (具体例境界Instructions 投入時)**:
  - Instructions に詳細な禁止ルール・誤字具体例（400文字超）を投入。
  - 結果: GPT-6 の深い文脈推論が裏目に出て「ルールに抵触しているのではないか」と疑心暗鬼になり、正常文の過検出（偽陽性）が 3件 ➡ **5〜8件へと急増**。正解率は 76.7%（F1: 0.788）に悪化。
  - コスト影響: プロンプトトークンが約 63 tokens から約 235 tokens へ約 3.7 倍に増加し、課金コストも 1 件あたり $0.00002 から $0.00004 へ倍増。
- **得られた知見**:
  - **Decisions API では過剰なルール詰め込みは逆効果**。二値の確率出力タスクにおいては、シンプル指示（50〜100文字）でモデル本来の自然言語理解に任せるのが最も高精度かつ低コスト。

## 4. 判定タスクにおける選定結論

- **見逃しゼロ（再現率 100%）を最優先する場合**:
  - **OpenAI Decisions API (`gpt-6-luna`) ＋ シンプル指示（閾値 0.4）**
  - わずかな過検出（FP）は許容し、次の補正フェーズで救済するパイプラインに適する。
- **低遅延（200ms帯）と誤報ゼロを最優先する場合**:
  - **TypeSafe AI System One (`jev-latest`) ＋ 最適化Criteria（閾値 0.2〜0.3）**
  - ユーザー入力中のリアルタイム警告や、誤報を嫌うUIフィードバックに最適。
